# Правила для всех ИИ-агентов в этом репозитории

Хакатон Островка 2026, трек «О!дин шаг до идеального отеля». Продукт — **«О!кно»**: сервис, который знает об отелях Сочи то, чего нет в карточке (вид из окна, путь до пляжа с подъёмом, шум, что рядом ночью), честно говорит, откуда это знает, и помогает выбрать отель без разочарований.

Над проектом работают двое людей, у каждого свой агент: владелец репо — Claude Code (читает `CLAUDE.md`), второй участник — любой агент (читает этот файл).
**Закреплённых зон нет: оба работают над всем — фронтом, бэкендом, данными.** Чтобы не мешать друг другу, действует одно правило: **каждая новая фича — в своей папке `features/<фича>/`** (см. ниже). Wiki ведёт Claude, остальные пишут в `wiki/inbox.md`.

## Прочитай перед работой (по порядку)
1. Этот файл.
2. `wiki/index.md` → `wiki/deliverables.md` (что должно быть в итоге) → `wiki/architecture.md` (структура, модель фактов, API).
3. `features/README.md` и README той фичи, над которой работаешь.
Концепция продукта — `wiki/product-concept.md`, требования организаторов — `wiki/requirements.md`.

## Главное правило структуры: одна фича = одна папка
```
features/<фича>/
  README.md     ← зачем, что делает, API, зависимости, критерии готовности, СТАТУС
  backend/      ← API и логика фичи (роутер подключается в app/)
  pipeline/     ← офлайн-расчёты фичи (результат → data/)
  frontend/     ← компоненты интерфейса фичи
core/           ← общее: гео-утилиты, LLM-клиент, БД, конфиг (без логики фич)
app/            ← точка входа: собирает роутеры фич, отдаёт фронт, /health
data/           ← демо-данные (маленькие — в git; большие — скачиваются скриптом)
wiki/           ← база знаний проекта (ведёт Claude, см. ниже)
raw/            ← неизменяемые источники (тексты организаторов, чаты) — не редактировать
mockups/        ← HTML-макеты интерфейса
```
- Новая фича → новая папка в `features/` + строка в `features/README.md`.
- Код фичи не лезет в чужие папки. Нужно от другой фичи — используй её публичный интерфейс (API или функции из её `backend/__init__`), не копируй.
- Общее для 2+ фич выноси в `core/`.

## Инварианты продукта (нарушать нельзя)
1. **LLM никогда не создаёт факты об отелях.** Факты считаются по данным или приходят от отельера. LLM только: понимает запрос гостя, ведёт диалог с отельером и разбирает его ответ, собирает спецификацию новой характеристики, перефразирует объяснение.
2. **У каждого факта есть источник, уверенность (0..1) и дата.** Уверенность — из качества данных, а не «на глаз». Схема `Fact` — в `wiki/architecture.md`.
3. **Всё работает без ключа LLM** (упрощённый режим: правила вместо LLM, заранее сохранённые диалоги).
4. **Не чат-бот.** Главный интерфейс визуальный (карта, линзы, «О!кно»). Текстовый ввод только настраивает интерфейс.
5. **Стиль Островка** — токены в `wiki/design-system.md`.

## Требования сдачи (жёсткие)
- `git clone` → `cp .env.example .env` → `docker compose up --build` → http://localhost:8080 за ≤10 мин, без ручных шагов.
- Контейнер слушает 8080; `/health` → `{"status":"ok"}` + healthcheck в compose; multi-stage; не root; `platform: linux/amd64`; версии зависимостей зафиксированы; логи в stdout.
- Тяжёлые расчёты — заранее, результат в `data/`. Большие файлы (DEM и т.п.) не коммитим — скрипт скачивания в `features/data_sources/pipeline/`.
- Сдача: тег `submission` на `main` до **29.10.2026 10:00 МСК**. Тег ставим только по договорённости обоих.

## Git
- Ветка на задачу: `feat/<фича>-<кратко>` (например `feat/okno-horizon`). В `main` — через PR или после короткого ревью второго человека.
- `main` всегда запускается (`docker compose up --build`).
- Коммиты: `<фича>: что сделано` (например `beach_route: время по Тоблеру туда и обратно`).
- Не трогай чужие незакоммиченные файлы; перед работой `git pull`.

## Как сообщать о сделанном
- Обнови раздел «Статус и заметки» в `features/<фича>/README.md`: что готово, пример запроса/ответа API, известные ограничения.
- Важные решения, изменения контракта API, найденные факты о данных → допиши строку в `wiki/inbox.md` (только дописывать в конец). Claude перенесёт это в wiki.
- **Не редактируй остальные страницы `wiki/`** — их ведёт Claude, чтобы не было конфликтов.
- Контракт API менять только с записью в `wiki/inbox.md` и в README фичи — фронт на него опирается.

## Стек (предложен, бэкенд может скорректировать — запиши в inbox)
Python 3.12 + FastAPI, SQLite (+JSON-поля), numpy/rasterio/shapely/pyproj/osmnx для гео, astral для солнца; фронт — React + Vite + MapLibre GL; один контейнер. LLM — OpenAI-совместимый API (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`).
