# Проект: хакатон Островка 2026, трек «О!дин шаг до идеального отеля»

**Общие правила репозитория для всех агентов — в `AGENTS.md`, прочитай его первым.** Ниже — дополнительные обязанности Claude (агент фронта/продукта).

Здесь ведётся **LLM wiki** (по схеме Karpathy): Claude владеет `wiki/`, человек кладёт источники в `raw/` и задаёт вопросы. Wiki — главная память проекта между сессиями. Перед любой работой прочитай `wiki/index.md`, затем нужные страницы.

## Слои
- `raw/` — **неизменяемые источники**: тексты организаторов, выдержки из чатов, слайды, извлечённые бренд-токены. Не редактировать, только добавлять новые файлы (имя с датой, если источник датирован).
- `wiki/` — страницы, которые пишет и поддерживает Claude. Синтез, решения, концепция, план.
- `mockups/` — HTML-макеты интерфейса (открываются в браузере, без сборки).
- Код: одна фича = одна папка `features/<фича>/`, общее в `core/`, вход в `app/` — см. `wiki/architecture.md`.
- `wiki/inbox.md` — сюда бэкендер и его агент дописывают новости; при каждой сессии переноси записи в wiki (ingest) и помечай `→ перенесено`.

## Формат страниц wiki
Каждая страница начинается с frontmatter:
```yaml
---
title: …
updated: YYYY-MM-DD
sources: [raw/…, …]     # откуда знание; пусто для чистых решений команды
status: draft | agreed | superseded
---
```
- Язык — русский. Коротко, по делу, таблицы и списки вместо простыней.
- Ссылки между страницами — относительные markdown-ссылки `[текст](other-page.md)`.
- Факт из источника → указывай источник. Решение команды → фиксируй в `decisions.md` с датой и причиной.
- Не дублируй: если знание уже есть на другой странице — ссылайся.

## Работа в команде
- Бэкендер и его агент не правят `wiki/` (кроме `inbox.md`) — правишь ты.
- Моя зона — фронт и продукт (`features/*/frontend/`, `app/` фронт-часть, `mockups/`, `wiki/`). В `backend/` и `pipeline/` бэкендера — только по договорённости.
- Перед работой `git pull`, работа в ветках `feat/<фича>-...`.

## Операции
- **Ingest** (новый источник от пользователя): сохранить в `raw/` → обновить затронутые страницы wiki → при новых фактах обновить `open-questions.md`/`decisions.md` → строка в `log.md` → поправить `index.md`.
- **Query**: отвечать по wiki; если ответ — новый ценный синтез, записать его в wiki.
- **Lint** (по просьбе или раз в день): противоречия между страницами, устаревшие утверждения, вопросы, на которые уже ответили, страницы без ссылок из `index.md`.

## `log.md`
Только дописывать в конец. Формат строки:
`- YYYY-MM-DD HH:MM · ingest|query|update|decision|lint · что сделано · затронутые страницы`
