# О!кно — трек «О!дин шаг до идеального отеля» (Ostrovok Hackathon 2026)

Сервис подбора отелей Большого Сочи, который знает то, чего нет в карточке: вид из окна по сторонам и этажам, путь до пляжа с подъёмом, шум по сторонам здания, что рядом. Каждый факт честно показывает, откуда он известен и насколько ему можно верить; чего не знаем — спрашиваем у отеля и сразу показываем ответ гостю.

- **Видео-скринкаст и презентация:** [Google Диск — папка с записью экрана и слайдами](https://drive.google.com/drive/folders/17PovSKeEuCPFo-Rq91_bjjesHDLnwwjs?usp=drive_link) (открывается без входа в аккаунт)
- **Развёрнутый сервис:** https://ostrovok-project.vercel.app (Vercel; LLM включён; база там временная — брони и ответы сбрасываются при перезапуске, для проверки по критериям используйте запуск в Docker ниже)

## Быстрый старт

```bash
git clone https://github.com/ostrovok-hackathon-2026/vot-takaya-vot-komanda-sobachka.git
cd vot-takaya-vot-komanda-sobachka
cp .env.example .env   # необязательно: без ключа LLM всё работает
docker compose up --build
# открыть http://localhost:8080
```

Кроме Docker и Docker Compose ничего ставить не нужно. Замер 28.10 на чистом клоне (MacBook, Apple Silicon): сборка без кеша — 24 с, плюс однократное скачивание базовых образов `node`, `python`, `postgres` (~1 ГБ); после сборки сервис отвечает на `/health` через 8 с.

**Ключ LLM для жюри** зашифрован в `secrets.env.age` (age, публичный ключ организаторов). Провайдер — [AITunnel](https://aitunnel.ru) (OpenAI-совместимый API), модель `qwen3.7-flash`. Чтобы включить LLM — расшифровать в `.env` и запустить как выше:

```bash
age -d -i <закрытый_ключ_организаторов> -o .env secrets.env.age
```

LLM необязателен: без ключа разбор фраз гостя и ответов отеля работает на правилах и морфологии (pymorphy3), всё остальное от LLM не зависит.

## Зависимости и переменные окружения

Рекомендованные ресурсы: **2 CPU, 2 ГБ RAM** для Docker (в работе: приложение ~450 МБ, база ~30 МБ), ~1 ГБ на диске под образы.

Сервисы в `docker-compose.yml`:
- `app` — приложение (FastAPI + собранный фронт React), порт `8080:8080`, процесс от пользователя `okno` (не root), healthcheck по `/health`, `platform: linux/amd64`;
- `db` — **PostgreSQL 16** (`postgres:16.6-alpine`), единая база сервиса: брони, ответы гостей и отелей, вопросы отелю, база знаний, характеристики агента. Порт наружу не открыт; `app` стартует после `db` (`depends_on: service_healthy`).
- Redis и другие сервисы не нужны.

Переменные (все необязательны, шаблон — `.env.example`):

| Переменная | По умолчанию | Что это |
|---|---|---|
| `APP_PORT` | `8080` | порт приложения внутри контейнера |
| `DB_URL` | `postgresql://okno:okno@db:5432/okno` (задан в `docker-compose.yml`) | единая база; без неё (запуск без Docker) — файл SQLite `data/runtime/okno.db` |
| `DB_PASSWORD` | `okno` | пароль PostgreSQL; база видна только внутри сети compose |
| `LLM_BASE_URL` | пусто (с ключом — `https://api.openai.com/v1`) | OpenAI-совместимый API |
| `LLM_API_KEY` | пусто — LLM выключен, работают правила | ключ LLM |
| `LLM_MODEL` | пусто | модель, для жюри `qwen3.7-flash` |
| `LLM_FALLBACK_BASE_URL`, `LLM_FALLBACK_API_KEY`, `LLM_FALLBACK_MODEL` | пусто | запасной LLM-провайдер: основной не ответил — запрос сразу уходит запасному |

Во время работы сервис ходит наружу только за тайлами карты (OpenFreeMap, запасной — CARTO), шрифтом (Google Fonts) и в LLM, если задан ключ. Отказ любого из них не роняет сервис: см. [`tests/`](tests/README.md).

## Сидирование

Ничего запускать не нужно — всё автоматически при старте:
- демо-данные (718 отелей из OpenStreetMap, расчёты вида из окна, шума, путей до пляжа, места рядом, тексты сайтов отелей) лежат в `data/seed/` в репозитории и попадают в образ;
- таблицы PostgreSQL создаются при первом обращении (`create table if not exists`);
- при первом старте в базу записываются демо: 2 прошедшие поездки с ответами «Так и было?», отзывы о Pullman, Azimut и Omega Sirius, общие знания по Сочи (туристический налог, вода в море, тип пляжей). Повторный старт ничего не дублирует.

Начать с чистой базы:

```bash
docker compose down -v && docker compose up --build
```

Пересчитать демо-данные из сырых источников — `sh tools/dev_check.sh` (нужны `data/raw/`: OSM и Copernicus DEM; для проверки решения не требуется).

## Маршруты и доступ

Веб-интерфейс на http://localhost:8080. **Входа нет, тестовые учётные данные не нужны** (демо): гость и отельер открываются по ссылкам.

| Адрес | Что там |
|---|---|
| `/` | поиск отелей: фильтры и «Опишите, что важно», карта, выдача |
| `/#<id отеля>`, например `/#w207579132` | карточка отеля: «О!кно», путь до пляжа, частые вопросы, бронь с пожеланием |
| `/#city` | город и «Что посмотреть» (клик по «Сочи» в шапке) |
| `/#compare/<id>,<id>` | сравнение отелей |
| `/#trip/<id брони>` | «Моя поездка» после брони: день, маршрут, «Так и было?» |
| `/#profile` | «Мои поездки» (кнопка «Профиль») |
| `/#extranet/<id отеля>` | экстранет отельера (кнопка «Для отелей»): вопросы гостей, ответы, брони с пожеланием |
| `/#admin` | «Научить О!кно»: новая характеристика описанием |
| `/health` | `200 OK`, `{"status": "ok"}` |
| `/health/deps` | состояние базы и LLM-провайдеров (без ключей и адресов) |
| `/docs` | все API-маршруты (OpenAPI) |

Основные API: `GET /api/hotels`, `GET /api/hotels/{id}`, `GET /api/hotels/{id}/window`, `GET /api/hotels/{id}/faq`, `POST /api/search`, `POST /api/describe`, `POST /api/bookings`, `GET /api/hotelier/{id}`.

## Что умеет
- **Поиск без фильтров:** «Опишите, что важно» → линзы «Вид на море», «Закат из окна», «Рядом пляж», «С пляжа не в гору», «Тихо ночью» и 36 фильтров «что рядом»; у каждого отеля — почему подходит и в чём нет.
- **О!кно:** вид из окна по сторонам и этажам для 209 отелей, закат над морем по месяцам; лучи видимости на карте.
- **Частые вопросы в карточке:** ответ отеля → посчитанное системой → общее для Сочи; нет ответа — «Спросить у отеля».
- **Экстранет отельера:** вопросы гостей со счётчиком спроса, ответ своими словами → «как мы поняли» → гость сразу видит ответ; подтверждение брони с пожеланием.
- **Бронь с пожеланием и «Моя поездка»:** пожелание из выбранного окна и этажа, ответ отеля, день по интересам, после поездки — «Так и было?», который сдвигает уверенность фактов.
- **Новая характеристика описанием** (`/#admin`): агент строит план поиска, проходит по всем отелям, чего не нашёл — спрашивает у отеля.
- **Отказоустойчивость:** без LLM — правила, запасной LLM-провайдер, запасная подложка карты, «Временная ошибка» вместо падения — отчёты и блок-схемы в [`tests/`](tests/README.md).

## Метрики
Все считаются без LLM и сети по демо-данным из `data/seed`; команды воспроизводят цифры. Замер 27.10, покрытие перепроверено 28.10.

**Покрытие и доля вопросов к отельеру** — `python features/metrics/pipeline/eval_coverage.py --md`. Агент характеристик проходит свой план по каждому из 718 отелей, как в сервисе, но вопросы не отправляет. *Надёжно* — источник ответил с уверенностью не ниже порога характеристики; *слабо* — ответ есть, но ниже порога (гость видит его с низкой уверенностью, отелю уходит вопрос); *нет данных* — открытые источники молчат, вопрос отелю.

| Характеристика | Надёжно (покрытие) | Слабо | Нет данных | Вопрос отелю |
|---|---|---|---|---|
| Путь до пляжа | 718 (100%) | 0 | 0 | 0% |
| Тихо ночью | 194 (27%) | 524 | 0 | 73% |
| Вид на море | 113 (16%) | 81 | 524 | 84% |
| Закат из окна | 109 (15%) | 24 | 585 | 85% |
| Wi-Fi в отеле | 163 (23%) | 0 | 555 | 77% |
| **5 основных вместе** | **36%** | 629 | 1664 | **64%** |
| «Что рядом», 36 фильтров вместе | 96% | 977 | 0 | 4% |

Вид из окна и шум по сторонам здания пока посчитаны для 209 отелей из 718 (нужен контур здания на карте); у остальных шум — грубая оценка по отелю целиком, а вид и закат спрашиваем у отельера. Это и есть основная очередь вопросов.

**Точность** — `python features/metrics/pipeline/eval_accuracy.py`. Разметка — цитаты с официальных сайтов отелей (собраны отдельно от расчёта, `features/web_sources`):

| Что сверяем | Выборка | Результат |
|---|---|---|
| До моря по прямой vs «N м до моря» на сайте | 35 отелей | 22 совпадают в пределах ±30% (63%), медианная ошибка 58 м |
| Минуты пешком по маршруту vs «N мин до моря» на сайте | 29 отелей | 18 совпадают ±3 мин (62%); у 9 (31%) путь в 1,5+ раза дольше обещанного |
| «Первая линия» на сайте | 7 отелей | у 6 пешком до пляжа не больше 400 м |
| Вид на море: сайт пишет «номера с видом на море» | 17 отелей с расчётом вида | море в окне найдено у 16, краешек — у 17 (по всем посчитанным: 66% и 91%) |

Оговорки: сайт отеля — не истина (расхождение в минутах — часто реклама отеля, ради этого и считаем маршрут); про вид сайты пишут только «есть», поэтому меряем полноту, а калибровку уверенности на такой выборке не оцениваем — для неё нужна ручная разметка с ответами «нет».

**Вид на море, слепая разметка** — `python features/metrics/pipeline/eval_sea_view_labels.py` (28.10). Разметку сделал агент по фото и отзывам из Яндекс Карт и сайтов отелей, без нашего расчёта: размечено 21 из 25, ещё 4 строки «?» (в подсчёт не входят). Точность «видно / не видно» (да и краешек против нет): верно 11 из 21 (52%); точный класс да / краешек / нет — 8 из 21. Калибровка: при уверенности ниже порога 0,5 (ответ «слабо», уходит вопрос отельеру) верно 4 из 11 (36%), средняя уверенность 0,43; при 0,5 и выше — 7 из 10 (70%), средняя 0,57.

**Было / стало** — `python features/compare/pipeline/eval_baseline.py`, 30 запросов по главным линзам: в 23 из 30 (77%) в первой десятке обычной выдачи есть отель с подвохом (шум, путь в гору, нет вида), в 12 из 30 (40%) — уже в топ-3. Подробно — [features/compare/README.md](features/compare/README.md).

**Разбор свободного ответа отельера** — `python features/hotelier/pipeline/eval_parse.py`: 55/55 полей на 25 размеченных ответах. Правила подбирались на этой же выборке, поэтому на новых ответах точность будет ниже; ошибку разбора ловит отельер на шаге «как мы поняли».

## Разработка без Docker
Команде и агентам: правила — `AGENTS.md` и `CLAUDE.md`, база знаний — `wiki/index.md`, список фич — `features/README.md`.

```bash
sh tools/dev_check.sh            # пересобрать демо-данные и фронт, поднять сервис на :8080
PORT=8090 sh tools/dev_check.sh  # на другом порту
```
Нужны `.venv` с `pipeline/requirements.txt` и скачанные `data/raw/` (OSM, Copernicus DEM).
