# Реестр характеристик и расширяемость

`features/characteristics/` · приоритет **P0** · закрывает: задачи 1 и 4

## Зачем (что видит пользователь)
Невидимо; в демо — добавляем характеристику текстом, и она появляется.

## Бэкенд / пайплайн → `backend/`, `pipeline/`
YAML-спеки характеристик в `features/characteristics/specs/`. Planner-агент: по спеке выбирает инструмент (viewshed, route, noise, poi_nearby, climate, ask_hotelier), запускает, пишет факты. Генерация новой спеки из текстового описания через LLM (с проверкой).

## Фронт → `frontend/`
Экран «добавить характеристику» (для демо/админки).

## API
`GET /api/characteristics`, `POST /api/characteristics/from-text`

## Зависит от
facts

## Готово, когда
- [ ] Данные/расчёт работают на демо-данных Сочи и лежат в `data/` (или воспроизводятся скриптом)
- [ ] Факты пишутся в хранилище с источником, уверенностью и датой (если фича производит факты)
- [ ] API отвечает по контракту выше, есть пример запроса/ответа в этом README
- [ ] Фронт показывает результат в стиле Островка (wiki/design-system.md)
- [ ] Работает без ключа LLM (fallback)

## Статус и заметки
- Статус: частично. Первый реальный реестр по описанию — каталог «что рядом» (`features/nearby/specs.json`, 25.10): новая характеристика добавляется записью без кода. Общий реестр для всех фич и «добавить текстом» через LLM — ещё нет.
- Владелец бэкенда: бэкенд · владелец фронта: фронт/продукт
