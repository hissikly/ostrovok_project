# Сравнение и отпечаток, «было / стало»

`features/compare/` · приоритет **P1/P2** · закрывает: доп.: сравнение; вопрос эксперта «повлияет ли»

## Зачем (что видит пользователь)
Сравнивает 2–4 отеля; видит обычную выдачу рядом с нашей и где обычная разочаровала бы.

## Бэкенд / пайплайн → `backend/`, `pipeline/`
Вектор характеристик отеля, похожие отели, базовая «обычная» сортировка (звёзды/цена/расстояние по прямой) для режима «было / стало».

## Фронт → `frontend/`
Таблица сравнения, отпечаток-глиф, режим «было / стало».

## API
`POST /api/compare`, `GET /api/hotels/{id}/similar`, `POST /api/search?baseline=true`

## Зависит от
search, facts

## Готово, когда
- [ ] Данные/расчёт работают на демо-данных Сочи и лежат в `data/` (или воспроизводятся скриптом)
- [ ] Факты пишутся в хранилище с источником, уверенностью и датой (если фича производит факты)
- [ ] API отвечает по контракту выше, есть пример запроса/ответа в этом README
- [ ] Фронт показывает результат в стиле Островка (wiki/design-system.md)
- [ ] Работает без ключа LLM (fallback)
