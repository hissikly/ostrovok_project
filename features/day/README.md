# Твой день здесь

`features/day/` · приоритет **P1 (киллер)** · закрывает: доп.: объяснение

## Зачем (что видит пользователь)
Видит ленту одного дня поездки из фактов: плюсы и подвохи.

## Бэкенд / пайплайн → `backend/`, `pipeline/`
Сборка ленты по дате и режиму поездки из фактов okno, beach_route, noise, nearby, climate.

## Фронт → `frontend/`
Лента дня в карточке отеля.

## API
`GET /api/hotels/{id}/day?month=5&facade=W&floor=16&mode=kids` — `facade`, `floor`, `mode` необязательны
(без стороны берётся запад или первая посчитанная; этаж — ближайший посчитанный, по умолчанию верхний).

```json
{"hotel_id": "w201474333", "month": 5, "facade": "E", "floor": 16, "mode": null, "built_at": "2026-10-26",
 "scenes": [{"time": "05:19", "icon": "sunset", "title": "Солнце заглянет в окно в 05:19",
             "note": "Рассвет в 04:56. Если любите поспать, пригодятся плотные шторы", "good": false,
             "fact_ids": ["w201474333:morning_sun:facade:E"], "facts": [{"source": "computed:horizon+sun", "confidence": 0.65, "…": "…"}]},
            {"time": "10:00", "title": "На пляж 8 минут пешком", "note": "Вниз 29 м, лестницы", "good": true, "…": "…"}]}
```
Публичная функция для других фич: `from features.day.backend import day`.

## Зависит от
facts, okno (`data/seed/okno`), beach_route, noise, nearby; climate и airport — подхватываются, когда появятся
(`features.climate.backend.climate(lat, lon, month) -> {"water": …}`, `features.airport.backend.arrival(hotel) -> сцена`).

## Готово, когда
- [x] Данные/расчёт работают на демо-данных Сочи и лежат в `data/`
- [x] Сцены несут факты с источником, уверенностью и датой («как узнали» по клику)
- [x] API отвечает по контракту выше
- [x] Фронт показывает результат в стиле Островка
- [x] Работает без ключа LLM (LLM не нужен вообще)

## Статус и заметки
- Статус: **v0 работает** (26.10, Claude).
- **Сцены** (только при наличии факта, по времени): утро — солнце в окне (подвох, если раньше 08:00) или «не разбудит»; 08:30 кофе (`near:cafe` ≤10 мин); 10:00 пляж — `beach_route` (вниз, лестницы, переходы, вода из climate); 13:00 обратно — подъём «как на N-й этаж», с ребёнком — «с коляской тяжело» при подъёме ≥15 м или лестницах; 17:00 детская площадка (с ребёнком); вечер — закат из «О!кна» для стороны/этажа и месяца, если не виден — смотровая рядом; 20:00 ужин (`near:restaurant`); 23:00 шум ночью по стороне + какая сторона тише; 23:30 круглосуточная аптека/магазин.
- **Утро в окне** — новый офлайн-расчёт `pipeline/morning_sun.py`: по полным профилям горизонта (`data/derived/okno`, есть у 209 отелей) для 15-го числа месяца ищет первую минуту, когда солнце выше угла закрытия в секторе окна ±80°. Результат — `data/seed/day_morning.json` (287 КБ, 12 с). Факт `morning_sun` отдаётся внутри сцены (в общее хранилище не регистрируется, чтобы не плодить строки в «Что важно знать»).
- **Пляж у «Чайки»**: если до берега по карте ≤150 м, а маршрут по графу на 10+ мин длиннее — граф не дошёл до ближайшего пляжа, берём замер по карте («Море прямо у отеля»). См. inbox 26.10.
- Проверено в браузере: Pullman (запад — закат в море и спокойно ночью; восток — солнце в 05:19, заката нет), Azimut (пляж 23 мин и подъём 101 м, север — шумно, «окна на запад тише»), «Чайка» (море у отеля, тихо), отели без «О!кна» — лента без утра и заката. Синхронизация со стороной/этажом «О!кна» и режим «С ребёнком» работают.
- Не сделано: прилёт (ждёт `airport`), вода/погода (ждёт `climate`), бар до 02:00 — в OSM-выгрузке нет `opening_hours`.
- В общих файлах: роутер в `app/main.py`, `<DayPanel>` в `HotelCard.jsx`, `onPick` в `WindowPanel.jsx`, `export` у `HOW` в `FactList.jsx`.
