# Хранилище фактов и достоверность

`features/facts/` · приоритет **P0** · закрывает: задача 3

## Зачем (что видит пользователь)
Видит у каждого факта источник, уверенность и дату; нажал — доказательство.

## Бэкенд / пайплайн → `backend/`, `pipeline/`
Модель `Fact` (см. wiki/architecture.md), запись/чтение, срок годности, статусы active/superseded/conflict/needs_review. Это ядро — им пользуются все фичи.

## Фронт → `frontend/`
Бейдж источника, кольцо уверенности, всплывающий «паспорт факта».

## API
`GET /api/hotels/{id}/facts`, `GET /api/facts/{fact_id}`

## Зависит от
hotels

## Готово, когда
- [ ] Данные/расчёт работают на демо-данных Сочи и лежат в `data/` (или воспроизводятся скриптом)
- [ ] Факты пишутся в хранилище с источником, уверенностью и датой (если фича производит факты)
- [ ] API отвечает по контракту выше, есть пример запроса/ответа в этом README
- [ ] Фронт показывает результат в стиле Островка (wiki/design-system.md)
- [ ] Работает без ключа LLM (fallback)

## Статус и заметки
- Статус: **v0 работает** (25.10, Claude) — хранилище в памяти: при старте читаются все `data/seed/facts_*.json`. Любая фича кладёт свой файл `facts_<фича>.json` по модели из `wiki/architecture.md` — и факты появляются в API и карточке. SQLite — когда появится онлайн-запись (отельер, «так и было?»).
- Публичный интерфейс: `from features.facts.backend import facts_for, all_facts`.
- id факта: `<hotel_id>:<characteristic>:<scope>`, например `w201474333:sea_view:facade:W`.
- Фронт: `FactList.jsx` (источник, сторона, дата, кольцо уверенности), `Ring` экспортируется.
