# Диалог с отельером и кабинет

`features/hotelier/` · приоритет **P1** · закрывает: задача 2, доп.: кабинет

## Зачем (что видит пользователь)
Отельер видит, что о нём знают, подтверждает/исправляет, отвечает своими словами; видит «упущенных гостей».

## Бэкенд / пайплайн → `backend/`, `pipeline/`
Генерация вопроса по недостающему/неуверенному факту; приоритет = спрос гостей × неуверенность; имитация отельера (LLM-персона с «правдой» об отеле); разбор свободного ответа в поля с подтверждением. Fallback без LLM — заранее сохранённые диалоги.

## Фронт → `frontend/`
Кабинет отельера: карточки на подтверждение, мессенджер вопросов, «упущенные гости».

## API
`GET /api/hotelier/{hotel_id}/questions`, `POST /api/hotelier/{hotel_id}/answers`

## Зависит от
facts, characteristics

## Готово, когда
- [ ] Данные/расчёт работают на демо-данных Сочи и лежат в `data/` (или воспроизводятся скриптом)
- [ ] Факты пишутся в хранилище с источником, уверенностью и датой (если фича производит факты)
- [ ] API отвечает по контракту выше, есть пример запроса/ответа в этом README
- [ ] Фронт показывает результат в стиле Островка (wiki/design-system.md)
- [ ] Работает без ключа LLM (fallback)

## Статус и заметки
- Статус: **очередь вопросов v0** (25.10, Claude). Экрана Экстранета и разбора ответа ещё нет (макет — `mockups/hotelier.html`).
- `backend/questions.py`: вопрос гостя → в очередь отеля. Тот же отель + та же тема (или тот же смысл фразы, если темы нет) → не новый вопрос, а `demand + 1`. Текст вопроса отелю — из каталога тем `features/knowledge/topics.json` (`ask_hotel`), без темы — фраза гостя. Хранение — SQLite `HOTELIER_DB` (по умолчанию `data/runtime/hotelier.db`, не в git).
- API: `POST /api/hotelier/{hotel_id}/questions {"topic": "pets"}` или `{"text": "где купить сим-карту"}` → `{id, topic, text, demand, status: "open", created}`; `GET /api/hotelier/{hotel_id}/questions` → открытые вопросы, сначала самые спрашиваемые.
- Владелец бэкенда: бэкенд · владелец фронта: фронт/продукт
