# Отели и базовая карточка

`features/hotels/` · приоритет **P0** · закрывает: ожидаемый результат

## Зачем (что видит пользователь)
Видит реальные отели Сочи на карте и их базовую карточку (звёзды, цена, фото — мок).

## Бэкенд / пайплайн → `backend/`, `pipeline/`
Список отелей из OSM, привязка к контуру здания и фасадам (нормали рёбер), этажность. Мок базовых полей карточки с пометкой «мок».

## Фронт → `frontend/`
Точки отелей на карте, шапка карточки отеля.

## API
`GET /api/hotels`, `GET /api/hotels/{id}`

## Зависит от
data_sources

## Готово, когда
- [ ] Данные/расчёт работают на демо-данных Сочи и лежат в `data/` (или воспроизводятся скриптом)
- [ ] Факты пишутся в хранилище с источником, уверенностью и датой (если фича производит факты)
- [ ] API отвечает по контракту выше, есть пример запроса/ответа в этом README
- [ ] Фронт показывает результат в стиле Островка (wiki/design-system.md)
- [ ] Работает без ключа LLM (fallback)

## Статус и заметки
- Статус: **v0 работает** (25.10, Claude)
- Данные: `pipeline/build_hotels.py` → `data/seed/hotels.json` (объекты размещения Сочи из OSM с названием) + `data/seed/facts_hotels.json` (высота над морем по DEM — первый вычисленный факт у каждого отеля). Цена/рейтинг/отзывы — мок (`mock`), детерминированный по id.
- Дубли: `pipeline/dedup.py` → `data/seed/hotel_dups.json`. Одно здание в OSM дважды (то же название ближе 50 м) — оставляем запись с большим числом фактов, остальные `hotels()` не отдаёт (22 из 718, в выдаче 696); по прямой ссылке дубль открывается.
- API: `GET /api/hotels` → `[{id, name, kind_ru, lat, lon, stars, price_rub, facts}]`; `GET /api/hotels/w201474333` → полная запись с `osm`, `address`, `levels`, `website`, `mock{price_rub, rating, reviews}`.
- Фронт: `HotelMap.jsx` (MapLibre, подложка OpenFreeMap без ключей; синие точки — отели с расчётом вида из окна), `HotelList.jsx`, `HotelCard.jsx`.
- id отеля = первая буква типа OSM + id: `w201474333` = way/201474333.
