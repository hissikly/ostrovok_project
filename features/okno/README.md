# О!кно — вид из окна

`features/okno/` · приоритет **P1 (киллер)** · закрывает: задача 1 (гео)

## Зачем (что видит пользователь)
Видит, что будет видно из номера на нужном этаже и стороне, и где сядет солнце в его даты.

## Бэкенд / пайплайн → `backend/`, `pipeline/`
Офлайн: профиль горизонта для каждого отеля × фасад × полоса этажей (лучи по DEM + здания), см. wiki/window-view-method.md. Факты: доля моря, «море с N этажа», закат по месяцам.

## Фронт → `frontend/`
Вид из окна (способ отрисовки — открытый вопрос), переключатели этажа/стороны/месяца.

## API
`GET /api/hotels/{id}/window?facade=W&floor=5`

## Зависит от
data_sources, hotels, facts

## Готово, когда
- [ ] Данные/расчёт работают на демо-данных Сочи и лежат в `data/` (или воспроизводятся скриптом)
- [ ] Факты пишутся в хранилище с источником, уверенностью и датой (если фича производит факты)
- [ ] API отвечает по контракту выше, есть пример запроса/ответа в этом README
- [ ] Фронт показывает результат в стиле Островка (wiki/design-system.md)
- [ ] Работает без ключа LLM (fallback)

## Статус и заметки
- Статус: **посчитаны все 209 отелей с контуром здания** (25.10, Claude). В сервисе 194: у 15 нет названия в OSM.
- Итог (28.10): вид на море у 138, только краешком у 52, без моря 19; закат над морем из окон у 143.
- **28.10: морем считается только открытое море** (`horizon.open_sea`: самая большая связная область DEM ≤ 0,5 м). Раньше любая точка ниже 0,5 м была «морем» — у «Омеги» (Сириус) лучи на восток над Имеретинской низменностью рисовались «видно море», восточная сторона давала 42% моря. Пересчёт: изменились 145 сторон у 63 отелей, доля моря нигде не выросла; «вид на море» потерял 1 отель (La Terrassa, 4-я линия), «краешек» — 1 («Арина», 2 этажа). Сверка с разметкой по фото не изменилась. Этажность: у 119 из OSM отеля, у 44 по корпусу, у 46 неизвестна → считаем 5 этажей (вопрос отельеру).
- Конвейер (весь — ~1 мин, кроме скачивания домов):
  1. `features/data_sources/pipeline/fetch_buildings.py` — дома OSM тайлами ~2×2 км вокруг отелей → `data/raw/buildings/` (41 тайл, 95 МБ, не в git).
  2. `pipeline/compute_all.py` — расчёт параллельно на всех ядрах (~25 с) → `data/derived/okno/<id>.json` (36 МБ, не в git). Один отель: `pipeline/window.py way/201474333`.
  3. `pipeline/export_seed.py` → `data/seed/okno/<id>.json` (11 МБ) + `data/seed/facts_okno.json` (факты `sea_view`, `sunset_view`).
- API: `GET /api/hotels/w201474333/window` → фасады/этажи и доля моря; `GET …/window?facade=W&floor=16` → `{floor, eye, eye_m, sea_share, sun[…], profile[[az, kind(b|t|s), dist, sea]]}` (с 25.10 без угла — он нужен только для заката, а закат уже посчитан). **С 25.10 считаются все этажи** (раньше 1, 2, 3, середина, верх — «море с 8-го» могло быть «с 5-го»): доля моря и закат — у каждого этажа, лучи для карты (`profile`) — только у 1, 2, 3, середины и верха, API отдаёт их с ближайшего (`profile_floor`). У 77 сторон из 819 «море с N-го этажа» стало точнее; данные 11 → 12 МБ, расчёт ~30 с. Во фронте при >8 этажах — полоска столбиков (высота = доля моря).
- Факт `sea_view.value`: `from_floor` (доля моря ≥30%), `glimpse_from` (≥5% — «краешком»), `share_by_floor`.
- Фронт: `WindowPanel.jsx` — сторона, этаж, вывод словами, закат; лучи и окно на основной карте.
- Известные ограничения: дома без этажности (~45%) — оценка по типу; деревья не учтены вблизи; на крутом склоне земля оценивается 10-м процентилем в радиусе 40 м. Метод — `wiki/window-view-method.md`, проверка — `wiki/data-check-sochi.md`.
