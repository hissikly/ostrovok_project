# Поиск: линзы, «опиши», ранжирование

`features/search/` · приоритет **P0** · закрывает: задача 5, ожидаемый результат

## Зачем (что видит пользователь)
Включает линзы или пишет фразу — город перекрашивается, подходящие отели светятся; видит «главное — первым».

## Бэкенд / пайплайн → `backend/`, `pipeline/`
Текст → потребности (LLM или правила-синонимы), скоринг отелей по фактам × уверенность, различающая сила фактов, объяснение из фактов по шаблонам.

## Фронт → `frontend/`
3D-карта, панель линз, ползунок времени, кнопка «✨ опиши», выдача.

## API
`POST /api/search`, `POST /api/describe`

## Зависит от
facts, все фичи-характеристики

## Готово, когда
- [ ] Данные/расчёт работают на демо-данных Сочи и лежат в `data/` (или воспроизводятся скриптом)
- [ ] Факты пишутся в хранилище с источником, уверенностью и датой (если фича производит факты)
- [ ] API отвечает по контракту выше, есть пример запроса/ответа в этом README
- [ ] Фронт показывает результат в стиле Островка (wiki/design-system.md)
- [ ] Работает без ключа LLM (fallback)
