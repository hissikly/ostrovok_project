# Моя поездка

`features/trip/` · приоритет **P1** · бриф 13 (`wiki/roadmap.md`), вобрал бронь из брифа 8 и весь бриф 11 «Так и было?» · закрывает: путь «после выбора отеля», задача 3 (достоверность растёт от ответов гостей), кабинет отельера

## Зачем (что видит пользователь)
Путь гостя продолжается после карточки: **Поиск → Отель → Бронь с пожеланием → Моя поездка → «Так и было?»**. Карточка отеля стала короче: в ней остаются три главные сцены дня, весь день с выходами из отеля и картой переехал в «Мою поездку».

## Что умеет
1. **Бронь с пожеланием (демо)** — блок «Бронирование» в карточке сразу после «О!кна». Пожелание собирается само из выбранных в «О!кне» стороны и этажа и фактов, без LLM:
   - сторона — с причинами: сколько моря из окна, закат над морем в месяц поездки;
   - этаж — с какого этажа вид почти такой же, как с выбранного (доля моря ≥ 95%): «Этаж 7 и выше — с 7-го этажа море почти как с 16-го»;
   - «Тихая сторона» — если выбранная сторона среди самых тихих, а другая громче на 5+ дБ: «На северной стороне ночью громче: рядом улица Орджоникидзе».
   Гость может убрать пункт крестиком. «Забронировать с пожеланием» → бронь в SQLite → экран `#trip/<id брони>`.
2. **Экстранет** — раздел «Брони с пожеланием» вверху «Что о вас знают гости»: пожелание и почему гость его просит; «Подтверждаем» или «Не сможем, предложим…» с текстом. Гость видит «Отель подтвердил» и ответ отеля (экран сам проверяет ответ раз в 4 с, пока ждёт).
3. **«Что мы вам обещали»** — 3–5 фактов, на которых держался выбор, для стороны и этажа гостя: море из окна, закат, путь к пляжу и обратно, ночь, одно — со слов отеля (бассейн, завтрак). Формулировки — из ленты «Ваш день», чтобы обещание звучало как карточка. По клику — как узнали, насколько уверены и сколько гостей подтвердили. Обещание сохраняется вместе с бронью.
4. **Чемодан из фактов** — правила данными в [`packing.json`](packing.json), не кодом. Три группы: «Взять с собой», «Не забыть до поездки», «Можно не брать». По клику — почему и откуда знаем. Нет факта — нет пункта. С ребёнком чемодан собирается, когда в «Гостях» шапки есть дети (`features/guests`); тогда у заголовка пометка «С ребёнком».
5. **Полный «Ваш день»** — `DayPanel` из `features/day` с выходами из отеля и маршрутом на карте (карта справа показывает отель брони).
6. **«Так и было?»** — «Поездка завершена» → по пункту обещания (и по пожеланию, если отель его подтвердил): Да / Нет / Не проверял. Ответы сразу видны в карточке отеля («Гости проверили на себе: Море из окна — 8 гостей подтвердили») и сдвигают уверенность исходного факта.

## Как это работает
- **Факты поездки** (`backend/context.py`): факты отеля (у фактов по сторонам — факт выбранной стороны), факты сцен «Ваш день» (утреннее солнце, утренний кофе, честный путь к морю: у отеля прямо у воды берём замер по карте, как лента), знания базы `kb:swim`, `kb:beach_type`, `kb:crib`, `kb:breakfast`.
- **Правило чемодана**: `{"id", "kind": "bring|remind|skip", "item", "icon", "mode": "kids|adults", "when": [{"fact": "beach_route", "path": "climb_back_m", "gte": 25}], "why": "Обратно с пляжа {beach_route.back_minutes} минут в гору…"}`. Условия `eq` (`null` — места рядом нет), `in`, `lt/lte/gt/gte`, `exists`; `$month` — месяц поездки; `why` может быть списком вариантов (берётся первый, где все поля нашлись); одинаковый `id` — срабатывает первое правило. Новое правило — строка в JSON, без кода.
- **Ответы гостей** → факт-наблюдение `characteristic: "guest_feedback"`, `source: "guest_feedback"`, `scope: "fact:<id исходного факта>"` через `register_provider` (`features/facts`). Уверенность исходного факта — байесовски: уверенность расчёта = априорная доля «так и было» весом 10 ответов, «да»/«нет» гостей добавляются, «не проверял» не считается; сдвиг не больше ±0,15. Карточка подставляет сдвинутую уверенность в «как узнали» и не показывает наблюдения отдельными строками.
- **«Нет» по факту со слов отеля** (сайт, ответ отеля) или по подтверждённому пожеланию → вопрос в очередь Экстранета (`features.hotelier.ask_hotel`, тема факта, если есть в каталоге).
- **Демо**: при первом старте — 6–12 имитированных ответов на каждый пункт обещания Pullman, Azimut и «Чайки» (окна на запад, верхний этаж, май), всего 108, `demo=1`; в «как узнали» написано, сколько ответов демо.
- **Хранение**: SQLite `TRIP_DB` (по умолчанию `data/runtime/trip.db`, не в git): `bookings`, `feedback`.
- LLM не используется: всё на правилах, ключ не нужен.

## API
- `GET /api/hotels/{id}/request?month=5&facade=W&floor=16&drop=quiet` — пожелание:
  ```json
  {"hotel_id": "w201474333", "facade": "W", "floor": 16, "month": 5, "min_floor": 7,
   "text": "Окна на запад, этаж 7 и выше, тихая сторона",
   "items": [{"id": "side", "text": "Окна на запад", "reason": "Море почти во всё окно, закат над морем в мае", "facts": [{"id": "w201474333:sea_view:facade:W", "source": "computed:horizon", "confidence": 0.65, "obtained_at": "…"}]},
             {"id": "floor", "text": "Этаж 7 и выше", "reason": "С 7-го этажа море почти как с 16-го", "min_floor": 7, "facts": […]},
             {"id": "quiet", "text": "Тихая сторона", "reason": "На северной стороне ночью громче: рядом улица Орджоникидзе", "facts": […]}]}
  ```
- `POST /api/bookings {"hotel_id": "w201474333", "month": 5, "facade": "W", "floor": 16, "drop": []}` → поездка целиком (как ниже).
- `GET /api/bookings?hotel_id=w201474333` → брони отеля, новые сверху: `[{id, hotel_id, month, facade, floor, wish, status: sent|confirmed|declined, status_text, hotel_reply, replied_at, finished_at, created_at}]`.
- `GET /api/bookings/{id}?kids=true` → `{…бронь, hotel: {id, name, address, lat, lon, price_rub, rating, reviews}, kids, promise: [{id, icon, title, note, facts, guests: {yes, no, unsure, demo, guests, confidence_before, confidence} | null}], packing: [{id, kind, icon, item, why, facts}], answers: {id пункта: yes|no|unsure}}`.
  Пример чемодана Pullman (запад, май): «Удобная обувь, не шлёпанцы — к пляжу ведут лестницы, обратно 9 минут в гору, подъём 29 м», «Коралловые тапочки — пляжи в Сочи в основном галечные», «Тёплая кофта на пляж — в мае море около 17°», можно не брать: «Большую аптечку — круглосуточная аптека «36,6» в 7 минутах», «Запас воды и перекусов — продуктовый «Кайрос» в 3 минутах»; с ребёнком ещё «Переноска вместо коляски», «Гидрокостюм ребёнку», «Заказать детскую кроватку».
- `POST /api/bookings/{id}/feedback {"answers": {"w201474333:sea_view:facade:W": "yes", "wish": "no"}}` — отмечает «Поездка завершена» (с пустым `answers` — только это), пишет ответы (повторный ответ по тому же пункту не принимается) → поездка целиком.
- `GET /api/hotelier/{id}/bookings` — брони с пожеланием для Экстранета; `POST /api/hotelier/{id}/bookings/{booking_id} {"answer": "confirm" | "decline", "text": "Север свободен только на 5 этаже, предложим запад, 12 этаж"}`.
- `GET /api/feedback/stats` — метрика: доля «так и было» по типам фактов.
- Публично для фич: `from features.trip.backend import wish, trip, summary`.

## Метрика «так и было»
`GET /api/feedback/stats` на демо-ответах (108 демо + 8 проверочных из браузера), доля «да» среди «да»/«нет»: вид на море 0,95, закат 0,87, путь к пляжу 0,85, море у отеля 1,0, шум 0,73, завтрак с сайта Azimut 0,77. Демо-ответы имитированы с заданными долями (`DEMO_YES` в `backend/feedback.py`): шум по карте оценить сложнее всего — поэтому у него и уверенность расчёта ниже (0,5). На настоящих ответах метрика покажет, какие расчёты калибровать первыми.

- Ограничения: бронь — демо (нет цены за номер, оплаты, дат кроме мая); у брони нет владельца — «Ваша поездка» в карточке показывает последнюю бронь отеля в этой установке. Демо-ответы подкладываются один раз, при пустой таблице ответов. Счётчик в карточке — своей строкой «Гости проверили на себе», а не внутри строки факта: строка факта — в `FactList` (фича facts), её не трогали.
- Слито с `feat/trip-plan` (27.10): в `app/main.py` роутер `trip_plan` подключён как `trip_plan_router` (имя `trip_router` занято); «С ребёнком» в чемодане берётся из интересов; в карточке маршрут дня на карте вернулся.
