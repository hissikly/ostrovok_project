# Сайты отелей (RAG)

`features/web_sources/` · приоритет **P1** · закрывает: задача 1 (LLM + RAG поверх открытых данных), задача 3 (источник и цитата), путь гостя «Частые вопросы»

## Зачем (что видит пользователь)
Многое знает только отель: питомцы, кроватка, парковка, трансфер, время заезда, бассейн. Мы читаем официальный сайт отеля (тег `website` в OSM) и показываем ответ с подписью «С сайта отеля»; по клику — **дословная цитата** и ссылка на страницу. Факт = цитата из источника, а не догадка.

## Как устроено
| Шаг | Файл | Что делает |
|---|---|---|
| 1 | `pipeline/crawl.py` | главная + до 10 страниц того же сайта по ключевым словам (номера, услуги, правила, питомцы, парковка…); robots.txt, 1 запрос/с на сайт, свой User-Agent; у сайтов сетей — только страницы этого отеля; сертификат не на этот домен → пробуем `http://` → `data/raw/web/<id>.json` (не в git) |
| 2 | `pipeline/index.py` | меню и подвал убираем, текст режем на чанки ~600 символов → `data/seed/web_chunks.json.gz` (1,1 МБ), `data/seed/web_sites.json` (статусы) |
| 3 | `pipeline/extract.py` | 17 тем (`topics.py`): без ключа — правила по предложениям сайта; `--llm` — модель отвечает по найденным чанкам, ответ проходит проверку `judge()` (ниже) и заменяет ответ правил. Слова гостей (отзывы на сайте) и вопросы из FAQ сайта — не факты → `data/seed/facts_web.json` |
| — | `backend/search.py` | BM25 по леммам (`core/textmatch`), индекс лениво на отель — инструмент `web_text` для агента |
| — | `backend/quote.py` | ответ на свободный вопрос с проверкой цитаты (LLM) или лучшее предложение (без ключа) |

Факт: `characteristic: "web:<тема>"`, `source: "web:<домен>"`, `evidence: {url, quote, fetched_at, topic}`, уверенность 0,7 (прямая формулировка) / 0,6 (косвенная, напр. «Люкс с балконом» → балкон в части номеров) / 0,5 (длинная фраза), срок годности 90 дней.

Перезапуск: `crawl.py --retry` (только не ответившие; **без VPN**) → `index.py` → `extract.py [--llm]`. Ключ — в `.env` (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`), ответы модели кэшируются в `data/raw/web/_llm_cache.json`, разбор принятых/отброшенных — `data/raw/web/_llm_report.json` (оба не в git). В офлайн-прогоне «размышления» модели выключены (`reasoning.enabled=false`): ответ всё равно проверяется цитатой, а прогон в ~10 раз быстрее (1800 вопросов ≈ 25 мин в 10 потоков).

**Когда ответ модели принимается** (`extract.judge`), иначе — отброшен с причиной:
1. цитата **дословно** есть в найденном куске сайта (с точностью до пробелов, регистра и «ё») — `quote_not_in_text`;
2. это не отзыв гостя и не вопрос из FAQ — `guest_or_faq`; цитата про тему, а не «рядом можно найти парковку» — `off_topic`;
3. каждое число ответа есть в цитате («тишина с 23:00» без времени в тексте — додумано) — `number_not_in_quote`;
4. «нет» сказано в цитате, а не выведено из молчания — `inferred_no`; «бесплатно» и «во всех номерах» — только если так и написано (иначе поле ослабляем);
5. значение укладывается в поля темы и не спорит с правилом на той же цитате — `bad_value`, `contradicts_quote`.

В `data/seed/facts_web.json` лежит **уже проверенный результат с моделью** — жюри ключ не нужен: это готовый seed, рантайм модель не вызывает. Без ключа `extract.py` воспроизводит режим правил.

## Где в интерфейсе
- **Частые вопросы** (`features/knowledge`): уровень `web` «С сайта отеля» — после ответа отеля и расчёта, раньше общего знания по Сочи. Темы с ответом на сайте добавляются в список карточки. Вопрос не из каталога («есть ли бассейн», «есть ли тренажёрный зал») → тема сайта или цитата из найденного куска; нет — как раньше «не знаем, спросить у отеля».
- **Что важно знать** (`features/facts`): одна строка «На сайте отеля пишут» — бассейн, свой пляж, кухня, Wi-Fi, лифт; по клику цитата.
- `sea_view` («все номера с видом на море») и `beach_claim` («5 минут до моря») не показываем — это обещания отеля для сверки с расчётом (`features/conflicts`).

## API
- `GET /api/hotels/{id}/web` → `{website, status, pages, fetched_at, facts: [...]}`
- `GET /api/hotels/{id}/web/search?q=тренажерный зал&k=4` → `[{text, url, title, fetched_at, score, matched}]` (инструмент `web_text`)
- `GET /api/web/stats` → сколько сайтов ответило, фактов, тем
- Публичный интерфейс: `from features.web_sources.backend import answer, ask, search, topics_for, web_facts`

Пример: `POST /api/hotels/n7164495092/ask {"text": "можно с собакой?"}` → «Можно с питомцем до 10 кг», `level: web`, цитата «В нашем отеле возможно размещение с животными до 10 кг.», ссылка ekodom-hotels.ru/akciya-pitomcy. Azimut `w51764141` тоже есть на сайте («до 15 кг, доплата 1500 ₽»), но у него демо-ответ отельера — он главнее.

### Сценарий для видео: «можно с собакой?»
1. Открыть `http://localhost:8080/#n7164495092` — отель **«ЭкоДом»** (3★).
2. В «Частые вопросы» ввести «можно с собакой?» → «Спросить».
3. Ответ «Можно с питомцем до 10 кг», подпись **«С сайта отеля»**; по клику — цитата «В нашем отеле возможно размещение с животными до 10 кг.» и ссылка на страницу сайта с датой проверки.
4. Запасной вариант: **Mantera Resort&Congress** `#w207637871` — «до 7 кг» + «для кошек и собак до 7 кг, при наличии ветеринарных документов» (manteracongress.ru/about).
5. Для сверки с сайтом: **RP Ranovsky Park** `#n10759606594` — сайт «10 минут пешком до пляжа», расчёт 22 мин и 25 мин обратно в гору на 89 м → «Отель пишет иначе» у гостя и карточка в Экстранете.

## Статус и заметки
- Статус: **v1** (26.10, Claude): обход без VPN, факты с моделью и строгой проверкой цитаты, сверка «сайт ↔ расчёт» в `features/conflicts`.
- **Обход 26.10 (с российского IP):** ответили **134 из 236** сайтов (57%; было 72 с VPN). Остальные: 43 — домен не резолвится (сайт умер), 5 — DNS есть, но не отвечает; 15 — пустая страница (сайт на JS, без браузера текста нет); 13 — 404, 8 — robots.txt запрещает (часто заглушка хостинга по http), 5 — сертификат не на этот домен и http тоже не открылся, 9 — прочие 4xx/5xx/таймауты, 2 — ссылки на агрегаторы (sutochno, booking), 1 — битый адрес. VPN (зарубежный IP) ломал 73 TLS-соединения и DNS ещё у ~60 сайтов.

- **Примеры глазами** (`_llm_report.json`):
  - ✅ модель лучше правил: «В номерах нет балконов.» → «В номерах нет балконов» (правило видело «балкон» → «в части номеров»); «Детские кроватки и дополнительные спальные места не предусмотрены.» → «нет» (правило — «есть»); «Проживание с животными возможно при условии, если питомец не более 5кг… 500р/сутки» → «до 5 кг, доплата 500 ₽»; «Час поселения в санатории 14.00. Расчетный час 12.00» → «заезд с 14:00, выезд до 12:00»; Богородск — правило взяло «30м до моря)» из отзыва, модель — «на самом берегу… 50 м» со страницы отеля.
  - ❌ отброшено: «Оснащение: ... кондиционер ...» — пересказ с многоточиями, на сайте так нет (`quote_not_in_text`); «Есть ли в номере стиральная машина? Нет.» как ответ про кухню (`off_topic`); «2 минуты до городского пляжа» → «своего пляжа нет» (`inferred_no`); «…соблюдать тишину» → «тишина с 23:00» (`number_not_in_quote`); «окна выходили прямо к аэродрому» — отзыв гостя (`guest_or_faq`); «Нет проблем найти рядом парковку» → «парковки нет» (`off_topic`, «рядом»).
  - ⚠️ остаётся: модель обобщает подпись «Трансфер» до «из аэропорта»; «парковка» в фразе «спросите про парковку — хозяин ответит» проходит как «есть парковка». Уверенность фактов модели 0,7, как у прямых формулировок правил.
- **Сверка «сайт ↔ расчёт»** (`features/conflicts`, `check_site`): `web:sea_view` и `web:beach_claim` против расчёта. Найдено **9 расхождений** — пляж: Ranovsky Park («10 минут пешком», маршрут 22 мин и 89 м в гору), «Пушкин» («10 минут», 33 мин), Marine Garden («4 мин», 14 мин), «Панорама» («7–10 минут», 16 мин), «Альфа» («20 мин», а пешком всего 6), «Лиссабон» («500 м», по прямой 802 м), Lavicon («200 м», 502 м), «Весна» («около 200 м», 460 м); вид: «Жемчужина» («со всех номеров панорамный вид на море», на восток моря почти не видно).
- **Агент в рантайме** (26.10, вечер): заранее скачан только текст сайтов (индекс RAG — как у любого RAG: обходить сайт во время вопроса гостя — секунды–минуты и половина сайтов не ответит). Сам ответ на свободный вопрос ищется в момент вопроса: ответы отеля и расчёты → темы сайта → поиск BM25 по страницам сайта → модель читает найденные куски → цитата сверяется с текстом дословно → нет ответа — «спросить у отеля». Каждый шаг пишется в `trace` ответа (`POST /api/hotels/{id}/ask` → `trace: [...]`), гость видит его по ссылке «Как искали». Факты по 17 темам в seed — это тот же агент, прогнанный заранее (`extract.py --llm`), чтобы карточка открывалась мгновенно и работала без ключа.
- **Скорость ответа:** было ~7 с (модель «размышляла»), стало 1,2–1,6 с (`core/llm.chat(..., think=False)`, таймаут 12 с); без ключа — мгновенно. Пока агент ищет, в «Частых вопросах» — «Смотрим ответы отеля → Сверяем с расчётами → Читаем сайт отеля…», прошлый ответ убирается.
- Ограничения: отзывы агрегаторов не скрапим (Q&A 27.10); эмбеддингов нет (BM25 хватает на сайт одного отеля).
