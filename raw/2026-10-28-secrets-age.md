# Шифрование секретов (ключей) — инструкция организаторов, получена 28.10.2026

Источник: страница организаторов, вставлена пользователем в чат 28.10. Выдержка по сути (без пересказа «частых ошибок»).

- Ключи (LLM и любые другие) передаются организаторам только зашифрованными: файл `secrets.env.age` в корне репозитория. Прочитать могут только организаторы (закрытый ключ у них).
- Публичный ключ: `age1932fu7f70rwyfhaxflyfszz4gf6avxwc95wc0yjwm6zns9tspycqpgdnc0`
- В репозитории должны быть: `secrets.env.age`; `.env.example` (имена без значений, с комментарием, откуда ключ); `.gitignore` со строкой `.env`.
- Открытый `.env` в репозиторий, чат и почту — нельзя.
- `.env`: по одной переменной в строке, без пробелов вокруг `=` и без кавычек, UTF-8 без BOM.
- Ключ LLM — отдельный, только для жюри; основной не передавать. В README — провайдер и модель.
- Шифрование: `age -r <ПУБЛИЧНЫЙ_КЛЮЧ> -o secrets.env.age .env` — всегда `-o`, без `-a` (бинарный формат). Изменили `.env` — зашифровать заново.
- `git ls-files .env` должна ничего не выводить. Если `.env` попадал в коммиты — ключи перевыпустить.
- Зашифрованный файл должен быть в ветке/теге сдачи.
- Проверка перед сдачей: `.env.example` есть; `.env` в `.gitignore`; `secrets.env.age` в корне, не пустой, значения не читаются; ключи отдельные для жюри; README — провайдер, модель, шаги запуска; после изменения `.env` файл пересоздан.
- Вопросы — в /help через @ostrovok_hackathon_bot (без ключей и содержимого .env).
