# Итоговое решение: чек-лист сдачи (29.10 до 10:00 МСК)

Три слоя: **(A)** без этого решение не примут/не оценят; **(B)** обязательное содержание по треку; **(C)** то, чем выигрываем. Подробности фич — [product-concept](product-concept.md), требования — [requirements](requirements.md).

## Где мы на 25.10 (разбор кода и пути гостя)
Сделано: карта 718 объектов Сочи из OSM, карточка в стиле Островка, хранилище фактов (`facts_*.json`, в памяти), у всех отелей — высота над морем по DEM, у **2** отелей — «О!кно» (`sea_view`, `sunset_view`), Docker проверен.

**Главный разрыв — обязательный результат не закрыт:** гость пока ищет только **по названию** (`HotelList.jsx`), а не по собранным характеристикам; осмысленные факты есть у 2 отелей из 718. Из пути гостя ([canvas](user-journey.canvas)) реализован только шаг «3. Выбираю отель → О!кно»; шагов «1. Хочу поехать» (контекст поездки), «2. Ищу» (линзы, «✨ опиши»), «4–6» нет. Отставание от плана §7 [product-concept](product-concept.md) — около дня.

Порядок закрытия (предложение, 26–28.10):
1. **Факты для всех отелей с контуром (~209):** вид на море/закат батчем + путь до пляжа с подъёмом (`beach_route`) — это и «≥1 гео-характеристика», и материал для поиска.
2. **Поиск по фактам:** линзы-переключатели + ранжирование `search` с учётом уверенности; «✨ опиши» на правилах (LLM — опционально).
3. **Доверие и влияние:** «мнения расходятся» + вопрос отельеру (имитация, предсохранённые ответы), «было / стало».
4. **Сдача:** README «как получены данные», `.env.example`, видео, чистый клон, тег.
Остальное (3D, ползунок времени, фасад, «Твой день», кабинет) — только после п. 1–2.

**Обновление 25.10, вечер:** п. 1 ведёт агент «О!кна». П. 2 сделан в v0 (`features/search`): 4 линзы, подбор по фактам, «✨ опиши» на правилах (+ LLM, если есть ключ); новый гео-факт «до пляжа» у всех 718 отелей (`features/beach_route`, пока по прямой). Обязательный результат формально закрыт: гость находит отель по собранным характеристикам. Слабое место — вид из окна у 2 отелей.

**Обновление 25.10, ночь:** вид из окна — 194 отеля; «что рядом» — 36 фильтров; **пешие маршруты по своему графу** по всему Сочи: путь до пляжа с подъёмом туда/обратно у 679 отелей, время «что рядом» по улицам, места по клику и маршрут до них на карте. **«О!кно» — все этажи; линза «Тихо ночью» по сторонам здания** — пример из задания «тихий номер с видом на закат недалеко от моря» закрыт целиком.

## B. Обязательный результат трека
«Работающий прототип для набора отелей выбранного региона, в котором пользователь может найти отель по собранным системой характеристикам».
- [ ] Набор реальных отелей Сочи (из OSM; базовые поля карточки — мок)
- [ ] Характеристики, которых нет в карточке, **собранные системой**; минимум одна — **вычислена по геоданным** (вид на море / путь до пляжа с подъёмом)
- [ ] У каждого значения: источник, уверенность, дата
- [x] Пользователь **находит отель** по этим характеристикам — линзы и «опиши» (`features/search`, 25.10)

## C. Что делает решение сильным
**Ответ на три вопроса эксперта** (обязательная «подача», хоть и не чек-лист):
- [ ] Важно ли ему → «главное — первым» под контекст поездки
- [ ] Можно ли доверять → доказательства, «мнения расходятся», калибровка уверенности
- [x] Повлияет ли на решение → режим «было / стало» *(27.10: в 77% из 30 типовых запросов в первой десятке обычной выдачи есть подвох по фактам, в 40% — уже в топ-3; `features/compare`)*

**Опорные задачи трека** (закрываем все — это то, что жюри ожидает увидеть):
- [ ] Агенты сами выбирают источник/инструмент под характеристику
- [x] Вопрос отельеру → свободный ответ → поля (отельер имитирован) — Экстранет, 25.10
- [x] Противоречия источников замечаются и разбираются — отель ↔ расчёт, `features/conflicts` (26.10)
- [~] Новая характеристика добавляется описанием, без переписывания кода — для «что рядом» да (`features/nearby/specs.json`, 25.10); «описать текстом» через LLM — нет
- [x] Поиск по своим словам («✨ опиши» → линзы; правила, LLM опционально — 25.10)

**Наши киллер-фичи (в порядке ценности для демо):**
1. [ ] 3D-карта с линзами и ползунком времени
2. [ ] «О!кно» — вид из номера + выбор окна на фасаде + пожелание к брони
3. [ ] «Твой день здесь»
4. [x] «Было / стало»
5. [ ] Кабинет отельера с «упущенными гостями»
6. [~] Сравнение ✅ (без отпечатка), «Так и было?» — в «Моей поездке»; «Пульс места» — нет

**Метрики в README** (маленькая своя разметка 20–40 отелей):
- [ ] точность вида на море и времени до пляжа, калибровка уверенности
- [ ] покрытие (доля отелей с надёжными фактами), доля вопросов к отельеру
- [ ] доля запросов, где наши факты меняют топ-3

## Чего в решении быть НЕ должно
- Фактов, которые придумала нейросеть («LLM угадала вид на море»)
- Чат-бота как главного интерфейса
- Зависимости от платного ключа для базовой работы
- Многочасовой загрузки данных при запуске
