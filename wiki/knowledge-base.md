# База знаний по уровням

Идея команды (25.10): ответы на частые вопросы гостей хранить базой знаний по иерархии места. Ниже — как это ложится на нашу модель фактов ([architecture](architecture.md)). Решения ещё нет: делать, скорее всего, будет бэкендер (`features/knowledge/` + `features/hotelier/`).

## Уровни
| Уровень | Пример знания | Откуда |
|---|---|---|
| Россия | нужен паспорт, отель регистрирует гостя | закон, открытые источники |
| Регион (Краснодарский край) | курортный сбор 50 ₽/сут | официальные данные |
| Город (Сочи) | купаются до середины октября, вода в мае 17° | Open-Meteo |
| Район (Адлер, Центр) | рядом аэропорт, днём самолёты | расчёт по карте |
| Отель | собак до 10 кг за 1000 ₽ | отельер |
| Сторона / номер | номера на запад с балконом | отельер, расчёт |

## Как устроить
- **Не отдельная база, а расширенное хранилище фактов.** У факта появляется путь «к чему относится»: `ru/krd/sochi/adler/w201474333/facade:W` — продолжение нынешнего `scope`.
- **Ответ ищем снизу вверх:** отель → район → город → регион → страна; гостю пишем, с какого уровня ответ («так ответил отель» / «общее правило для Сочи»). Отель противоречит уровню выше → «мнения расходятся».
- Хранение — SQLite (появляются записи на лету: ответы отельера).

## Агент — цепочка шагов, а не чат-бот
1. Понять вопрос гостя → характеристика (синонимы как в «опиши»; LLM, если есть ключ).
2. Найти ответ по уровням — обычный поиск, без LLM.
3. Нет ответа → вопрос отельеру в очередь (приоритет — спрос гостей).
4. Свободный ответ отельера → поля (LLM или шаблоны) → «как мы поняли» на подтверждение.
5. Записать факт на нужный уровень, проверить противоречия.
Ответ, которого нет в базе, не придумывается никогда.

## Когда спрашивать отельера
- **Заранее** — частые вопросы, которых нет в данных (питомцы, шумоизоляция, этажность у 46 отелей): отельер отвечает один раз, ответ видят все.
- **В момент поиска** — ответа нет: «не знаем, спросим у отелей»; вопрос уходит только отелям, подошедшим гостю по остальным пожеланиям (первые ~10 выдачи); отелю видно, сколько гостей спрашивали.

Гость видит в карточке блок «Частые вопросы» с пометкой источника; нет ответа — кнопка «Спросить у отеля», не чат.
