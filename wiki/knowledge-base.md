# База знаний по уровням

Идея команды (25.10): ответы на частые вопросы гостей хранить базой знаний по иерархии места. Ниже — как это ложится на нашу модель фактов ([architecture](architecture.md)). Решения ещё нет: делать, скорее всего, будет бэкендер (`features/knowledge/` + `features/hotelier/`).

## Уровни
| Уровень | Пример знания | Откуда |
|---|---|---|
| Россия | нужен паспорт, отель регистрирует гостя | закон, открытые источники |
| Регион (Краснодарский край) | курортный сбор 50 ₽/сут | официальные данные |
| Город (Сочи) | купаются до середины октября, вода в мае 17° | Open-Meteo |
| Район (Адлер, Центр) | рядом аэропорт, днём самолёты | расчёт по карте |
| Отель | собак до 10 кг за 1000 ₽ | отельер |
| Сторона / номер | номера на запад с балконом | отельер, расчёт |

## Как устроить
- **Не отдельная база, а расширенное хранилище фактов.** У факта появляется путь «к чему относится»: `ru/krd/sochi/adler/w201474333/facade:W` — продолжение нынешнего `scope`.
- **Ответ ищем снизу вверх:** отель → район → город → регион → страна; гостю пишем, с какого уровня ответ («так ответил отель» / «общее правило для Сочи»). Отель противоречит уровню выше → «мнения расходятся».
- Хранение — SQLite (появляются записи на лету: ответы отельера).

## Агент — цепочка шагов, а не чат-бот
1. Понять вопрос гостя → характеристика (синонимы как в «опиши»; LLM, если есть ключ).
2. Найти ответ по уровням — обычный поиск, без LLM.
3. Нет ответа → вопрос отельеру в очередь (приоритет — спрос гостей).
4. Свободный ответ отельера → поля (LLM или шаблоны) → «как мы поняли» на подтверждение.
5. Записать факт на нужный уровень, проверить противоречия.
Ответ, которого нет в базе, не придумывается никогда.

## Когда спрашивать отельера
- **Заранее** — частые вопросы, которых нет в данных (питомцы, шумоизоляция, этажность у 46 отелей): отельер отвечает один раз, ответ видят все.
- **В момент поиска** — ответа нет: «не знаем, спросим у отелей»; вопрос уходит только отелям, подошедшим гостю по остальным пожеланиям (первые ~10 выдачи); отелю видно, сколько гостей спрашивали.

Гость видит в карточке блок «Частые вопросы» с пометкой источника; нет ответа — кнопка «Спросить у отеля», не чат.

## Кабинет отельера — раздел внутри Экстранета (25.10)
У Островка уже есть **Экстранет** (веб + приложение «Ostrovok! Extranet», общий для Emerging Travel Group): цены и наличие, номера, условия, бронирования, чат с гостями **с бронью**, ответы на отзывы, счета. Не нашли там: вопросов гостей **до брони**, «что о вас знают гости», спроса гостей. Источники: [App Store](https://apps.apple.com/us/app/-/id6468881223), [справка ETG](https://help.extranet.emergingtravel.com/en/).

Поэтому не строим отдельный кабинет, а показываем **новый раздел Экстранета «Что о вас знают гости»** — макет `mockups/hotelier.html`:
- **Вопросы от гостей** по приоритету (спрос × неуверенность): «47 гостей искали отель с собакой». Ответ — свободным текстом или быстрыми кнопками → «Как мы поняли» (поля) → «Всё верно» → факт с источником «отельер», виден всем гостям.
- **Что мы узнали сами** (вид из окна, закат, пляж, что рядом): «Верно» / «Исправить». Поправка отеля **заменяет** расчёт («Уточнено отелем»), спора не показываем — см. [decisions](decisions.md) 25.10.
- **Справа — «Так увидит гость»**: блок «Частые вопросы» карточки отеля обновляется сразу после ответа; ответы уровня региона («курортный сбор — правило края»).
- В демо спрос и ответы отельера **смоделированы** с пометкой; разбор ответа — тот же механизм, что для настоящего.

## План реализации
| Шаг | Что | Где |
|---|---|---|
| 1 | Уровни в фактах (`ru/krd/sochi/…/отель`), SQLite, поиск ответа снизу вверх; 3–5 знаний уровня края/города | `features/knowledge/` (+ `facts`) |
| 2 | Каталог частых вопросов (~12) с синонимами и полями ответа | `features/knowledge/specs.json` |
| 3 | Очередь вопросов отельеру: приоритет = спрос × неуверенность; первый реальный — этажность 46 отелей | `features/hotelier/` |
| 4 | Разбор свободного ответа: вопросы с готовыми вариантами + числа шаблонами; LLM — если есть ключ | `features/hotelier/` |
| 5 | Противоречия: отель против расчёта → побеждает отель, расчёт в истории; спор только между отелем и отзывами гостей «Так и было?» или между открытыми источниками | `features/conflicts/` |
| 6 | Экраны: раздел Экстранета; «Частые вопросы» + «Спросить об отеле» в карточке; в поиске чип «пока не знаем» + «спросить у подходящих отелей» | фронт фич |
| 7 | Имитация 5–10 отелей с пометкой «демо»; метрика: точность разбора на 20–30 размеченных ответах | `features/hotelier/`, `features/metrics/` |

## Статус (25.10)
Шаги 1–2 плана сделаны: `features/knowledge/` — каталог 15 тем, уровни, поиск ответа (отель → посчитано → город/край/страна), API `/faq` и `/ask`. Знания уровня Сочи: туристический налог (2%, мин. 100 ₽ — в 2026 это **налог, а не курортный сбор 50 ₽**), тип пляжей (OSM), вода по месяцам (Open-Meteo). Подробно — `features/knowledge/README.md`.
