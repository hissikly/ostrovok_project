# О!кно — концепция v2 (трек «О!дин шаг до идеального отеля»)

> Не чат-бот и не фильтры. Пользователь **смотрит** на город и на отель так, как увидит их в поездке: из окна, в свои даты, в своё время суток. Всё, что мы знаем об отеле, превращено в картинку, а не в список галочек. За каждой картинкой — посчитанный и проверяемый факт.

Регион: **Большой Сочи** (Центр, Хоста, Адлер). Рельеф, море на западе, закаты, ж/д вдоль берега, аэропорт — каждая характеристика здесь реально решает.

---

## 1. Главная идея интерфейса: «машина времени» над 3D-городом

Экран — полноэкранная 3D-карта Сочи (рельеф + здания). Не поисковая строка, а три вещи:

```text
┌──────────────────────────────────────────────────────────────────────────┐
│  ПОЕЗДКА:  12–19 мая · 👨‍👩‍👧 с ребёнком · 🚶 без машины        [ ✨ опиши ]   │  ← контекст, а не фильтры
├────────┬─────────────────────────────────────────────────────────────────┤
│ ЛИНЗЫ  │                                                                 │
│ 🌊 море │            3D-город: рельеф, здания, море                       │
│ 🌅 закат│     отели светятся тем ярче, чем больше линз совпало            │
│ 🤫 тихо │     включённые линзы раскрашивают сам город                     │
│ ⛰ усилие│                                                                 │
│ 🌙 ночь │                                                                 │
│ 👶 дети │                                                                 │
│ 💻 связь│                                                                 │
├────────┴─────────────────────────────────────────────────────────────────┤
│  ⏱  06:00 ─────────●──────────── 23:00    май ▾      ← ползунок времени   │
└──────────────────────────────────────────────────────────────────────────┘
```

### 1.1 Линзы вместо фильтров
Каждая характеристика — **слой, который раскрашивает город**, а не галочка:
- 🌊 **Море** — здания подсвечены по тому, *с какого этажа* из них видно море (градиент по высоте фасада).
- 🌅 **Закат** — фасады, из которых в выбранный месяц видно солнце, садящееся в море.
- 🤫 **Тишина** — «тепловая карта шума», которая **меняется ползунком времени**: в 23:00 в субботу загораются бары и клубы (по `opening_hours`), днём — трасса, ночью — поезда.
- ⛰ **Усилие** — улицы окрашены по тому, сколько идти **обратно с пляжа в гору** (не по прямой, а по рельефу). Синие — ровно, красные — «в жару будет тяжело».
- 🌙 **Ночь** — что работает рядом после полуночи (аптеки, магазины, еда).
- 👶 **Дети** — площадки, пешеходные зоны, время до детской больницы.
- 💻 **Удалёнка** — покрытие 4G/5G (OpenCellID) + тишина днём + кафе с розетками.
- 🚗 **Машина** — можно ли подъехать ко входу, парковки, зарядки.
- 🐕 **Питомец** — площадки для выгула + политика отеля (от отельера).

Отель на карте — светящаяся точка: яркость = насколько он закрывает включённые линзы. Пересечение линз видно глазами: «вот этот квартал — и тихо, и море, и до пляжа ровно».

### 1.2 Контекст поездки вместо фильтров
Даты, «с кем», «как передвигаемся» — это **режимы**, которые сами включают нужные линзы и пересчитывают всё под даты:
- «с ребёнком» → линзы *дети*, *усилие*, *тишина ночью*;
- даты → климат (температура воды!), закат именно в эти дни, стройки и фестивали в эти даты;
- «прилетаем в 01:30» → дорога из аэропорта ночью.

### 1.3 «✨ Опиши» — не чат, а заклинание
Маленькая кнопка. Пользователь пишет «хочу просыпаться с видом на море и чтобы ночью было тихо» → строка **растворяется в интерфейсе**: на глазах включаются линзы 🌊🤫, ползунок прыгает на 23:00, город перекрашивается. Текст — это просто быстрый способ настроить визуальный интерфейс; результат всегда в картинке, а не в сообщении бота.

### 1.4 «Как в том отеле» — поиск по образцу
Перетаскиваешь отель, где уже был (или любой из выдачи) на кнопку «ещё такие» → находим отели с похожим **отпечатком** (см. 2.4), можно «такой же, но ближе к морю/дешевле».

## 2. Карточка отеля: четыре киллер-фичи

### 2.1 🪟 «Окно» — посмотри из номера до брони  ⭐ главная
Панорама 360° **из конкретного окна**, вычисленная из рельефа и зданий:
- силуэт горизонта: горы, соседние дома, **полоса моря** (синим — сколько её видно);
- **дуги солнца** на выбранные даты: где оно встаёт и где садится, видно ли закат из этого окна;
- ползунок **этажа** (1→12): двигаешь — и соседний дом «уходит вниз», море появляется с 4-го этажа;
- переключатель **фасада** (С/В/Ю/З).

Это одновременно и самая эффектная картинка, и **доказательство**: панорама — это и есть расчёт видимости, не рендер «для красоты».

Дополнительно (если успеем): «облёт» 3D-камерой MapLibre из точки окна с правильным положением солнца и неба.

### 2.2 🏢 Интерактивный фасад — выбирай окно, а не номер
Здание отеля в 3D (или «развёртка» фасадов), окна раскрашены: 🌊 море, 🌅 закат, 🤫 тихая сторона, 🔊 шумная. Клик по окну → «Окно» из этой точки.
Итог — **«рекомендация к брони»**: «просите западную сторону, этаж ≥4». Она прикрепляется к бронированию как пожелание отелю. Это и есть «на месте без разочарований» — и прямая польза для Островка (меньше отмен).

### 2.3 🎞 «Твой день здесь» — сторибординг поездки
Вместо списка характеристик — **лента одного дня** в выбранные даты, собранная из фактов:

```text
 07:40  ☀️ Солнце в окне восточной стороны (вы — на западной, не разбудит)
 09:00  🚶 На пляж: 7 мин вниз, через подземный переход под ж/д
 09:10  🌊 Вода в мае: 17°C — бодрит. Воздух 21°C            (Open-Meteo, 10 лет)
 13:00  🥵 Обратно: 11 мин в гору, +42 м — в полдень тяжело с коляской
 20:24  🌅 Закат над морем из вашего окна                       (расчёт, 4+ этаж)
 23:00  🔊 Бар «…» в 140 м работает до 02:00 — окна на запад тихие, на восток нет
 01:30  💊 Круглосуточная аптека — 6 мин пешком
```
Каждая строка кликается → доказательство (маршрут с профилем высот, источник, дата). Читается как история, а не как таблица, и сразу показывает и плюсы, и подвохи.

### 2.4 🧬 Отпечаток отеля
Компактный визуальный «паспорт» — круговой глиф из лепестков-характеристик (длина = значение, насыщенность = уверенность). Узнаётся с одного взгляда, позволяет:
- **сравнивать** 2–4 отеля наложением отпечатков + таблицей «где выигрывает каждый»;
- **искать похожие** (косинусное сходство по вектору фактов).

### 2.5 Честность встроена в дизайн, а не в сноску
- У каждого факта — **кольцо уверенности** и иконка источника (🛰 расчёт, 🗺 OSM, 🌦 климат, 🏨 отельер, 📄 карточка).
- Наведение → «паспорт факта»: метод, входные данные, дата, срок годности.
- **«Мнения расходятся»**: расчёт говорит «вида нет», отельер — «есть с 3 этажа» → обе версии рядом + «уточняем у отеля».
- **«Не знаем»** — тоже честный статус, с кнопкой **«Мне тоже важно»**: голос гостя повышает приоритет вопроса отельеру (см. 3.2).

## 3. Сторона отельера и Островка

### 3.1 Кабинет отельера: «Что о вас знают гости»
- **Карточки на подтверждение** (подтвердить / исправить / «не знаю»): «Мы считаем, что с 4-го этажа западной стороны виден закат. Верно?».
- **Вопросы агента** — в виде мессенджера; отельер отвечает свободным текстом («собак до 10 кг пускаем за 1000 р/сутки, кошек нет») → агент показывает, *как понял* (поля), отельер жмёт «да».
- **«Упущенные гости»** ⭐: «На этой неделе 47 человек искали *тихий номер* в вашем районе. Вы подходите по расчёту, но шумоизоляция не подтверждена — ответьте на 1 вопрос». Это мотивирует отельера отвечать и показывает Островку бизнес-ценность.

### 3.2 Агент спрашивает то, что важно гостям (value of information) ⭐
Вопросы отельеру не рассылаются «на всё подряд». Приоритет вопроса =
`спрос гостей на характеристику × неуверенность в факте × сколько решений он изменит`.
Спрос берётся из линз, поисков «✨ опиши» и кнопок «мне тоже важно». Так система собирает данные **там, где это реально влияет на выбор**, и минимизирует нагрузку на отельера. Метрика: доля вопросов, ответ на которые изменил ранжирование.

### 3.3 «Пульс места» — актуализация
Лента изменений по отелю: «рядом выдано разрешение на строительство — вид на море может пропасть», «в даты вашей поездки фестиваль на набережной — шумно до 23:00», «OSM: открылся новый бар в 80 м — пересчитали тишину». Срок годности фактов + перепроверка по расписанию.

### 3.4 «Обещание» после брони (концепт, мок)
Всё, что мы показали гостю, сохраняется как «обещание»: «вид на море с 4 этажа, тихо ночью, 7 мин до пляжа». После поездки — 3 тапа «так и было?». Ответы возвращаются в уверенность фактов и в метрики. Замыкаем цикл качества и даём Островку измеримое «меньше разочарований».

## 3.5 Важно ли, можно ли доверять, повлияет ли (уточнение эксперта 24.10)

Эксперт: собрать много данных «в вакууме» мало, **частью задания являются три вопроса** ([raw](../raw/chat/2026-10-24-evening-track2.md)). Наш ответ на каждый:

| Вопрос | Как отвечаем в продукте | Как докажем |
|---|---|---|
| **Важно ли это именно ему?** | Показываем не все факты, а 3–5 главных под контекст поездки («с ребёнком» → подъём, вода, аптека). Порядок = вес потребности × **различающая сила** факта: если у всех отелей одинаково — не показываем, выбрать это не помогает. Подпись «показываем, потому что вы едете с ребёнком» | Доля показанных фактов, по которым кандидаты реально различаются |
| **Можно ли доверять?** | Уверенность из качества данных, доказательство в один клик, «источники согласны» / «мнения расходятся», подтверждение отельера, «12 гостей подтвердили вид» (из «Так и было?») | **Калибровка**: на размеченных отелях факты с уверенностью 80% верны ~в 80% случаев — график в README |
| **Повлияет ли на решение?** | Режим **«было / стало»**: обычная выдача (звёзды, цена, «800 м до моря») рядом с нашей; помечаем, где обычная привела бы к разочарованию («обратно 15 мин в гору», «закат закрыт домом»). Цена компромисса: «вид на море — +1 200 ₽/ночь» | Доля запросов, где наши факты меняют топ-3; число «ловушек», которые мы поймали |

Вопросы отельеру тоже приоритизируются по влиянию на решение (см. 3.2). «Было / стало» — сильная сцена для видео.

## 5. Как это устроено (архитектура)

```text
 ОФЛАЙН (pipeline/, результат коммитим в seed/)
   Overpass/OSM ─┐
   Copernicus DEM ┼─▶ Tools: viewshed · route3d · noise(t) · poi(t) · climate · cells · wiki · photos
   Open-Meteo …  ─┘                │
   characteristics/*.yaml ─▶ Planner-агент ─▶ Facts(source, confidence, evidence, ttl)
                                   │              │
                         HotelierAgent ◀── VOI-приоритизатор (спрос × неуверенность)
                                   │
                              Verifier (противоречия, перепроверка, «Пульс»)

 ОНЛАЙН (backend FastAPI + frontend React/MapLibre, один контейнер :8080)
   /api/lenses/{id}?t=…  → GeoJSON/векторные слои для раскраски города (предпосчитаны по часам/месяцам)
   /api/hotels?ctx=…     → скоринг по фактам × уверенность
   /api/hotels/{id}/window?facade&floor&month → панорама (профиль горизонта + дуги солнца)
   /api/hotels/{id}/day?dates&mode → лента дня из фактов
   /api/describe         → текст → линзы/режимы/время (LLM или правила)
   /api/hotelier/*       → вопросы, ответы, подтверждения, «упущенные гости»
```

Ключевые решения:
- **Все тяжёлые расчёты офлайн.** Viewshed: для каждого отеля 4 фасада × полосы этажей × 360 лучей → профиль горизонта (угол возвышения по азимуту + тип препятствия: рельеф/здание/море). Из него на лету рисуется «Окно» и считается закат на любые даты.
- **3D-карта:** MapLibre GL JS + `raster-dem` тайлы, сгенерированные из Copernicus для bbox Сочи (лежат в репо, единицы МБ) + `fill-extrusion` зданий. Подложка — OpenFreeMap / OSM (без ключей).
- **LLM нигде не создаёт факты.** Только: «✨ опиши» → настройки интерфейса, диалог с отельером → поля, YAML новой характеристики из описания. Без ключа — правила/синонимы и предсобранные диалоги; интерфейс работает полностью.
- **Расширяемость:** характеристика = YAML (инструмент + параметры + ttl + вопрос отельеру + как рисовать линзу). Новую можно описать текстом → агент собирает YAML из реестра инструментов.
- Стек: Python 3.12, FastAPI, SQLite, numpy/rasterio, osmnx/networkx, shapely, suncalc/astral; React + Vite + MapLibre + d3 (панорама, отпечаток). Docker multi-stage, non-root, `linux/amd64`, `/health`.

## 6. Приоритеты (что точно, что если успеем)

**P0 — фундамент (без этого не сдаём):** список отелей Сочи на 3D-карте; вид на море и усилие до пляжа (геоданные); факты с источником/уверенностью/датой; вопрос отельеру + парсинг ответа; поиск/ранжирование по линзам; YAML-расширяемость; Docker/README/видео.

**P1 — киллер-фичи для демо:** 🪟 «Окно» с ползунком этажа и солнцем; линзы с ползунком времени (тишина ночью); 🎞 «Твой день здесь»; интерактивный фасад + рекомендация к брони; кабинет отельера с «упущенными гостями»; «✨ опиши».

**P2 — если останется время:** отпечаток + похожие; сравнение; «Пульс места»; VOI-приоритизация вопросов на реальных «кликах»; облёт 3D-камерой; удалёнка/OpenCellID; фото Mapillary; «Обещание»; метрики на разметке (лучше всё же сделать хотя бы маленькую).
