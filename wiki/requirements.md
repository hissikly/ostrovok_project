# Требования трека и правила сдачи

## Суть трека
- Слайд на открытии: «Переизобретите опыт бронирования отелей: от вдохновения и выбора направления до оплаты и управления поездкой. AI, данные и новые интерфейсные механики…».
- Текст трека: прототип **агентной системы**, которая собирает уникальные характеристики отелей и номеров из открытых данных и у отельеров, систематизирует, хранит и показывает пользователю.
- Уточнение эксперта (Ilia Marashli, 23.10): **суть не в DS**. Цель — соединить «хочу поехать» с конкретным отелем, минимум усилий, без разочарований на месте. Геоданные — примеры, не рамки. **Фундамент:** знать об отеле то, чего нет в карточке, и уметь сказать, откуда это известно. Остальное (флоу, ввод желания, роль отельера, момент брони) — свобода.
- Уточнение эксперта (24.10 18:31): **подходить шире** — знать много об отеле «в вакууме» не решает проблему. Частью задания являются также: **важны ли эти данные конкретному пользователю, насколько им можно доверять и повлияют ли они на его решение**.
- Данных/API Островка **не дают**. Источники — открытые (OSM, DEM, публичные API). LLM, который «угадывает» вид на море, — не решение.

## Что обязательно (ответ Ilia Marashli, 24.10 18:26)
**Обязателен только «Ожидаемый результат».** «Основные» и «Дополнительные» задачи — видение организаторов и опорные пункты, не чек-лист. Критерии оценки **не опубликуют вообще** (даже 28.10).

## Основные задачи (опорные, не обязательные)
1. Сбор характеристик: агент сам выбирает источники/инструменты; **≥1 характеристика вычисляется по геоданным**.
2. Диалог с отельером: вопрос → свободный ответ → поля. Отельера можно имитировать.
3. Хранение и достоверность: источник, уверенность, дата у каждого значения; противоречия замечаются.
4. Расширяемость: новая характеристика без переписывания (например, описанием текстом).
5. Поиск по запросу своими словами.

## Дополнительные задачи
Объяснение выбора · сравнение · кабинет отельера · актуализация · метрики качества.

## Ожидаемый результат — ОБЯЗАТЕЛЬНО
«Работающий прототип для набора отелей выбранного региона, в котором пользователь может найти отель по собранным системой характеристикам.» Один регион — рекомендовано. Демо-данные — в репозитории, с описанием, как получены (базовые поля карточки можно мокать). Ключ LLM — описать в README + `.env.example`.

## Техника (обязательно)
- Код только в репо команды в орге `ostrovok-hackathon-2026`.
- Файлы: `README.md`, `docker-compose.yml`, `Dockerfile`, `.env.example`.
- `git clone` → `cp .env.example .env` → `docker compose up --build` → http://localhost:8080, ≤10 мин, без ручных доустановок.
- Контейнер слушает 8080; `/health` + healthcheck в compose; multi-stage; не root; `platform: linux/amd64` при сборке на Apple Silicon; фиксированные версии; логи в stdout.
- Большие модели не в git — OpenAI-совместимый API.
- **Видео-скринкаст обязателен** (доступен в инкогнито).
- README по шаблону: описание, ссылка на видео, быстрый старт, ресурсы/переменные, сидирование, маршруты (`/`, `/health`).
- Допустимо дополнительно: ссылка на развёрнутый сервис / доступ к серверу.
